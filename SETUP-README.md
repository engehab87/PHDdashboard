# Palm Hills HCP Dashboard — Laptop Setup

These scripts prepare your laptop to run the **Palm Hills Community Operations Intelligence Platform** backend and reach the on-site HCP server through the FortiClient VPN profile you already have configured.

They follow the requirements described in the HCP Integration API Specifications (Oct 2026).

---

## What the scripts do

| Step | Action |
|------|--------|
| 1 | Verify Node.js (≥ 20 recommended, 24 preferred) and npm |
| 2 | Create `data/` directory for uploads, raw files and backups (database is remote PostgreSQL) |
| 3 | Generate a secure `HCP_VAULT_KEY` (or keep an existing one) |
| 4 | Write / update a `.env` file with all required variables |
| 5 | Check whether `forticli.exe` is present and optionally show VPN status |
| 6 | Run `npm install` if `package.json` is present |
| 7 | Print the exact next steps for connecting the VPN, configuring a compound, running the 9-stage diagnostic, and starting a sync |
| 8 | Optionally start the backend (`--start` / `-StartServer`) |

---

## Quick start (Windows – recommended)

1. Place the scripts **inside the real project root** (the folder that contains `package.json`, `backend/`, etc.).

2. Open PowerShell in that folder and run:

   ```powershell
   # Basic setup (VPN control left disabled – safest)
   .\setup-dashboard.ps1

   # Or enable backend-managed VPN control
   .\setup-dashboard.ps1 -EnableVpnControl

   # Setup + start the server in one go
   .\setup-dashboard.ps1 -StartServer
   ```

3. Connect the FortiClient tunnel **manually** for the first runs:

   - Open FortiClient → select the profile that already works → Connect.
   - Confirm you can reach the HCP host (ping, browser, or `curl`).

4. Start the backend (if you did not use `-StartServer`):

   ```powershell
   npm start
   ```

5. Configure a compound in the UI or via API (see below) and run the 9-stage diagnostic.

---

## Quick start (any OS – Node helper)

```bash
node setup-dashboard.js                  # generate .env + checks
node setup-dashboard.js --enable-vpn     # also set FORTICLIENT_ENABLED=true
node setup-dashboard.js --start          # try to launch the server afterwards
```

On macOS / Linux the FortiClient CLI path will almost certainly be wrong; leave `FORTICLIENT_ENABLED=false` and connect the VPN with the GUI (or your platform’s CLI) yourself.

## Required environment variables

| Variable | Purpose | Default / Example |
|----------|---------|-------------------|
| `HCP_VAULT_KEY` | 64-hex AES-256-GCM key (mandatory for secrets) | generated by the script |
| `PORT` | Backend listen port | `2020` |
| `DATABASE_URL` | Azure PostgreSQL connection string (required) | `postgresql://user:password@server.postgres.database.azure.com:5432/db?sslmode=require` |
| `FORTICLIENT_ENABLED` | Let the backend call `forticli.exe` | `false` |
| `FORTICLIENT_CLI` | Full path to the CLI binary | `C:\Program Files\Fortinet\FortiClient\forticli.exe` |
| `FORTICLIENT_TUNNEL` | Exact name of the tunnel profile | `PHNC-Tunnel` |
| `HCP_HEALTHCHECK_MS` | Background health-check interval | `300000` (5 min) |

A ready-to-edit template is also provided as `.env.example`.

## Compound configuration (minimum for live data)

When you create or update a compound (`PUT /api/hcp/compounds/:id`), set at least:

```json
{
  "name": "Site Main",
  "enabled": true,
  "network": {
    "hcp_host": "192.168.15.15",
    "hcp_port": 443,
    "https": 1,
    "tls_verify": 1
  },
  "hcp": {
    "hcp_version": "2.6.0",
    "openapi_version": "2.6",
    "camera_index_code": "<YOUR_CAMERA_INDEX_CODE>"
  },
  "creds": {
    "app_key": "<YOUR_APP_KEY>",
    "app_secret": "<YOUR_APP_SECRET>"
  }
}
```

- If the HCP certificate has CN=`127.0.0.1` (or any SAN mismatch), either ask IT to re-issue it or pin the approved CA PEM in the compound’s `tls_ca` field.
- `camera_index_code` is **required** for the vehicle / access-events category; without it that category is blocked.

## Recommended first-run sequence

1. **VPN** – connect the tunnel manually and verify reachability.
2. **Backend** – start with the generated `.env`.
3. **Compound** – create/configure with correct host, versions `2.6.0` / `2.6`, credentials, and camera index.
4. **Diagnostic** – `POST /api/hcp/compounds/:id/test` → poll `GET /api/hcp/runs/:runId`.
5. **Review the 9 stages** – especially `tls`, `auth`, `adapter-compat`, and `sync-state`.
6. **Sync** – only after the gate is open (`POST /api/hcp/compounds/:id/sync`).

## Current hard blockers (from the API specification)

Even with a perfect VPN tunnel these will still stop live data until resolved:

| Blocker | Reason | Action |
|---------|--------|--------|
| Adapter `verified: false` | Sync gate requires `verified === true` | After a successful live test, mark the adapter verified (or temporarily relax the gate for development only). |
| Official Hikvision docs not in repo | Live auth/fetch is blocked by design until verification | Same as above. |
| TLS certificate mismatch | CN=127.0.0.1 / SAN problem | Pin CA or obtain a correct certificate. |
| Missing `cameraIndexCode` | Vehicle & access-event categories are blocked | Obtain the correct index code from the HCP administrator. |

## Security notes while the laptop is the server

- The dashboard currently has **no application-level authentication** (trusted-intranet assumption). Restrict access with the Windows firewall, bind to `127.0.0.1`, or put a reverse proxy with auth in front.
- Keep `HCP_VAULT_KEY` secret and outside git / web root.
- Prefer leaving `FORTICLIENT_ENABLED=false` and connecting the VPN by hand until you trust the CLI automation.
- All real HCP traffic is read-only; biometric data is never retrieved.
